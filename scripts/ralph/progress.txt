## Codebase Patterns
- Projection run manifests record resolved generating flags plus OS/Python/numpy
  versions. Rebuilds target float-ULP equality across platforms and byte identity on
  the generating platform. Combined R3+R4 team tables keep `e_wins`, `e_games`, and
  `e_shutout_wins` R3-only while `e_goalie_points` carries the documented fold.
- Evaluation reports must disclose excluded events and reasons. In opponent membership
  replay, missing snake order is an explicit manifest/report exclusion, never a silent
  drop.
- Guard globally keyed overrides with structured ids plus `expected_matches`.
  `match-drafts` counts skaters by the effective lookup name (`corrected_name` when
  present, else raw) and team overrides by the first matching G-slot team/raw
  candidate. Legacy scalar ids remain supported for unguarded overrides.
- When parser diagnostics live in pandas `DataFrame.attrs`, aggregate them before
  concatenation and copy them into the command result object; pandas operations do not
  provide durable user-facing accounting by themselves.
- Committed evidence provenance uses one regeneration pass: every model, backtest, and
  projection manifest SHA must equal `ml/artifacts/EVIDENCE_PASS.json` and carry
  `git_dirty=false`. Never compare provenance to current HEAD ancestry; squash merges
  and shallow clones may not retain the generating commit object.
- Duplicate draft ownership uses the asset identity consumed by the slot: `player_id`
  for skaters and `team_id` for goalie/team slots, scoped by league, season, and draft
  event. Goalie rows deliberately skip skater goals-plus-assists point cross-checks.
- Tests that consume gitignored `data/normalized` tables must skip with a clear missing-
  data reason on fresh clones. README must list the normalize, league-draft matching,
  and odds generation sequence needed to enable those real-data regressions.
- Draft-night inputs fail closed at the shared CLI boundary: `parse_managers` rejects
  case-insensitive duplicate ids for both `draft` and `recommend`, `_resolve_eliminated`
  rejects every unmatched abbreviation, and `DraftState.new` validates uniqueness
  again. New sessions never overwrite an existing path; use `--resume` or a distinct
  `--session`. `--resume A --session B` refuses an existing distinct `B`; in-loop
  `resume <path>` switches autosave to that resumed path. Both recommend entry points
  share the fitted-opponent coverage label.
- Game-win reports/manifests record per-season priced/total market coverage with the
  temporal split and explicit zero-coverage state. Odds joins can promote
  `season_end_year` to float, so normalize group keys before integer conversion.
- Committed projection artifacts ship CSV/parquet twins. Structural tests must compare
  ordered rows and columns after blank-string/null normalization, with `1e-12` relative
  and absolute float tolerance for CSV round trips.
- Combined-event manifest components are independently serialized to six decimal
  places; formula decomposition tests need `3e-6` absolute tolerance.
- Odds source cross-validation must compare one consistent side (`home_implied`), not

  orientations, but market joins are orientation-specific; reverse-only archive matches

  declared `total` and `len(data)` because capped responses can omit `total`.
- Combined-event regression tests must assert concrete cross-round numbers, not only

  league comparisons independently so one working leg cannot mask another regression.

  fn of league size N + roster shape (SPEC 1) — F=(5N+1)-th, D=(3N+1)-th,

- Multi-step recommendation (US-021, `optimize/recommend.py`): `recommend_pick(state,
  owner, model)` = argmax over legal candidates of expected FINAL owner-roster
  projection via MC rollout to draft end (opponents draft through all owner turns; owner
  future slots filled by greedy-VOR tail; avg >=500 seeded rollouts). PERF (<10s at
  12-mgr first pick): the pick ORDER is identical across rollouts, so batch all 500 in
  numpy — `_vectorized_greedy_expected` advances [R,P] alive/counts arrays in lockstep,
  Gumbel-max samples the greedy opponent, only opponent draws differ (used when
  opponents are a single `GreedyOpponentModel`; mapping/fitted uses the OO path). Also:
  prune candidates to top `max_candidates` by VOR, stop each rollout at owner-full,
  survival computed only for the surfaced top_n. CRITICAL variance fix — COMMON RANDOM
  NUMBERS: seed rollout j from j ALONE (not the candidate) so all candidates face the
  same opponent draws; without CRN the candidate value gaps (<0.5) drown in rollout
  variance and the lookahead picks near-randomly / loses to greedy. `asset_value` =
  projection (fallback rank_value); `greedy_vor_pick` = argmax value-minus-replacement.
  `oracle recommend --artifact-dir <projection-dir> --managers N --seat S`.
- Strategy comparison honesty (US-021): use SINGLE-DECISION same-slot framing ("from the
  same slot") — advance to a shared decision slot with a greedy tail, each strategy makes
  ONE pick, finish with an identical greedy-VOR tail; measure final owner value. Do NOT
  run each strategy at EVERY owner pick (recursive tail/policy mismatch: the rollout
  assumes a greedy tail but actual play uses lookahead -> biased, lookahead can lose).
  KEY FINDING: against BALANCED opponents greedy-VOR is already optimal (fitted opponents
  draft positions evenly because `rank_z` is standardized WITHIN a position), so
  multi-step correctly TIES it — a tie is the honest, expected result, not a bug. The
  multi-step advantage only appears against POSITIONAL-RUN opponents (a run pushes a
  position below its pool-wide replacement, where a static VOR board is blind) — the
  committed `artifacts/models/recommend/report.md` runs BOTH scenarios and reports both.
