- Cross-package imports: @sportsnot/nhl-api available in @sportsnot/supabase via tsconfig path aliases (no package.json dep needed)
- Supabase Realtime: Use `supabase.channel('name').on('postgres_changes', {...}).subscribe()`, cleanup with `supabase.removeChannel(channel)` in useEffect

## 2026-02-14T01:42 - US-007
- What was implemented: Two new Supabase Edge Functions for stat syncing
  - sync-player-stats: Accepts player_ids array, season, playoff_round in request body. Fetches each player's playoff game log from NHL API, aggregates goals/assists/games_played, and upserts into player_stats_cache table.
  - sync-team-stats: Accepts team_abbreviations array, season, playoff_round in request body. Fetches playoff bracket to determine team IDs and elimination status. Fetches recent scores to count wins/shutouts. Upserts into team_stats_cache table with is_eliminated flag.
  - Both functions use onConflict upsert to prevent duplicates
  - Both return JSON with updated count, total, and any errors
  - Input validation: returns 400 if required array is empty
  - Error handling: individual player/team failures don't stop the batch
- Files changed:
  - packages/supabase-db/functions/sync-player-stats/index.ts (new)
  - packages/supabase-db/functions/sync-team-stats/index.ts (new)
- **Learnings for future iterations:**
  - Edge Functions are Deno-based; imports use https://esm.sh/ URLs, not npm packages
  - Each Edge Function lives in its own directory under packages/supabase-db/functions/<name>/index.ts
  - supabase-db has no tsconfig; Edge Functions are not typechecked by the web tsconfig (they use Deno types)
  - NHL playoff bracket API at /playoff-bracket/{season} provides team IDs, names, and abbreviations via topSeedTeam/bottomSeedTeam

## 2026-02-14T01:45 - US-008
- What was implemented: PostgreSQL triggers for auto-recalculating roster and member points when stats change
  - `recalculate_player_points()` function: fires on player_stats_cache INSERT/UPDATE, calculates points as goals + assists (1 pt each), updates all active roster slots referencing the player, then recalculates league_members.total_points
  - `recalculate_team_points()` function: fires on team_stats_cache INSERT/UPDATE, calculates points as (wins - shutouts) * 2 + shutouts * 4 (shutout replaces win points), updates all active roster slots referencing the team, then recalculates league_members.total_points
  - Separate INSERT and UPDATE triggers: INSERT fires on all new rows, UPDATE uses `WHEN (OLD.* IS DISTINCT FROM NEW.*)` to avoid unnecessary recalculations
  - Idempotent: re-running produces the same result since points are recalculated from current stats (not deltas)
- Files changed:
  - `packages/supabase-db/migrations/002_stats_recalculate_triggers.sql` (new)
- **Learnings for future iterations:**
  - PostgreSQL `WHEN (OLD.* IS DISTINCT FROM NEW.*)` clause is only valid for UPDATE triggers, not INSERT (OLD is null for inserts) — split into separate INSERT and UPDATE triggers
  - Scoring rules: goal=1, assist=1, win=2, shutout=4 where shutout replaces win points (a shutout IS a win, so formula is (wins-shutouts)*2 + shutouts*4)
  - Triggers iterate over all active rosters matching the player_id/team_id — this means all leagues are updated when stats change
  - league_members.total_points is recalculated by SUM of active roster slot points_earned
  - Migration files go in packages/supabase-db/migrations/ with sequential numbering
