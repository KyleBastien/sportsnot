## Codebase Patterns
- Game-win reports/manifests record per-season priced/total market coverage with the
  temporal split and explicit zero-coverage state. Odds joins can promote
  `season_end_year` to float, so normalize group keys before integer conversion.
- Committed projection artifacts ship CSV/parquet twins. Structural tests must compare
  ordered rows and columns after blank-string/null normalization, with `1e-12` relative
  and absolute float tolerance for CSV round trips.
- Odds source cross-validation must compare one consistent side (`home_implied`), not
  each source's favorite-probability magnitude. Game-type lookup may index both
  orientations, but market joins are orientation-specific; reverse-only archive matches
  must be retained as uncovered and counted. NHL stats-rest truncation guards check both
  declared `total` and `len(data)` because capped responses can omit `total`.
- Combined-event regression tests must assert concrete cross-round numbers, not only
  `scored_rounds` metadata. Guard roster actuals, conditional goalie valuation, and
  league comparisons independently so one working leg cannot mask another regression.
- Game-win targets come from normalized `team_games.win`, not goal comparison:
  shootouts have equal `goals_for` totals. `_pivot_games` retains rows with exactly
  one archive winner and warns before excluding malformed/undecided rows.
- League draft consumers must call `dedupe_duplicate_events` before aggregation and
  use shared `event_keys` grouping; real events are keyed by
  `(season, league_name, draft_event)`, never season/event alone. Dedupe preserves
  asset-level `points_excluded=True` from any source before preferring app rows and
  fills missing app skater `team_id` values from an unambiguous matching sheet row.
  Never overwrite app team ids or apply this supplement to goalie/team rows.
- Mock TanStack Query-shaped results must expose every status field consumed by shared
  hooks; successful static results include `isFetched: true`.
- On Windows, `yarn nx e2e @sportsnot/e2e` can start Playwright before `serve-static`
  listens on port 4200. If early tests fail with `ERR_CONNECTION_REFUSED`, start
  `yarn nx serve-static @sportsnot/web`, verify readiness, then run Playwright directly.
- Team outcome feature ownership (US-119): `models/game_win.py` owns chronological
  team aggregates and exact-game market joins; `models/series_sim.py` consumes the
  fitted game model. Shared Elo config/math lives in `features/elo.py`. Do not add a
  parallel team/series matrix unless a production path consumes and evaluates it.
- Clean artifact regeneration (US-118): `add_git_provenance()` inspects Git from the
  Python process working directory. Importing source from a detached clean worktree
  via `PYTHONPATH` is insufficient if the process CWD remains a dirty checkout. Run
  inside the clean worktree and write artifacts to an external directory so earlier
  generated rounds do not make later manifests dirty.
- Artifact provenance (US-117): every model/projection/backtest manifest writer must
  wrap payloads with `draft_oracle.provenance.add_git_provenance`; this stamps both
  `git_sha` and an explicit `git_dirty` marker so dirty-tree artifacts cannot claim
  clean reproducibility.
- Draft-time CLI startup (US-117/US-208): keep `cli/project.py` imports stdlib +
  Typer only and keep `optimize/__init__.py` convenience re-exports lazy. Artifact
  consumers must import lightweight primitives (for example `optimize/ir_pool.py`),
  not modules that import projection training. Guard REAL `draft` and `recommend`
  runs with `lightgbm`, `sklearn`, and `httpx` blocked; `--help` alone misses command
  body imports. Default draft session state belongs in cwd, never inside immutable
  artifact fixtures. Tests are offline by enforcement: `tests/conftest.py` blocks
  socket connections globally; HTTP tests must inject `httpx.MockTransport` or
  another in-memory fixture transport.
- Recommend fast path vs object rollout (US-116, `optimize/recommend.py`): two
  rollout impls must stay reconciled. The OBJECT path (`_expected_value` ->
  `_rollout_owner_value`) is the source of truth: opponents draft by `rank_value`
  (`GreedyOpponentModel`/`FittedOpponentModel`), the owner fills greedy-VOR by
  `asset_value`, and E[roster] = `_owner_roster_value` = sum of asset_value over the
  owner's WHOLE roster (already-drafted + rollout picks). The VECTORIZED paths
  (`_vectorized_greedy_expected`, `_vectorized_fitted_expected`) must match: score
  opponents by `rank_val` (NOT `val`/projection), and add
  `base_owner_value = _owner_roster_value(state, owner)` to every candidate mean
  (owner_total only accumulates rollout picks). Dry states: any pick site must call
  `_require_legal_rows(legal, manager)` (raises like the object path) -- a bare numpy
  `argmax` over an all -inf row silently returns index 0 and drafts garbage; the
  owner greedy TAIL (`_vec_fill_owner`) instead masks per-row and STOPS (matches
  `_fill_owner_greedily`'s break). GOTCHA: fast==object EXACTLY only at temperature 0;
  parity tests must advance the draft so the owner holds >=1 asset (else
  base_owner_value=0 hides the m-8 bug) and, to exercise the dry-raise, make the
  OWNER the last snake seat on the clock (object stops at owner-full, so an opponent
  that only runs dry afterward won't raise).
  Exact opponent-utility ties use `rank_value` descending then asset key ascending;
  never inherit vector array order (currently projection-sorted). Fitted kernels keep
  `need_weight` in a manager-indexed array alongside rank/affinity coefficients. CLI
  labels must disclose league-average/no-affinity behavior when `seatN` ids match no
  fitted per-manager keys.

- IR-stash valuation (US-022, `optimize/ir_value.py`): IR activation is a RETROACTIVE

  `max(stash, starter)` (`retroactive_swap_points`), never additive. Marginal
  `stash_value = E[max(X - Y, 0)]`, Y = US-018 replacement level for that position
  (F swaps F, D swaps D). Compose US-015 `ReturnTimeModel.availability_curve(status)`
  (fit spells pre-cutoff, leakage-free; degenerate fallback when no spells) + US-016
  `simulate_round_points`. Verdict "stash" iff stash_value beats the healthy
  replacement-level alt (`healthy_alternative_value`: ppg = baseline/E[len], fully
  available). Cheat sheet gets an IR section via `CheatSheet.ir_section` (pre-rendered

- VOR / draft-board pattern (US-018, `optimize/vor.py`): replacement level is a PURE
  fn of league size N + roster shape (SPEC 1) — F=(5N+1)-th, D=(3N+1)-th,
  G/team=(N+1)-th; IR adds +1 F/+1 D per manager (6N+1 / 4N+1), never a goalie slot.

  demand>=supply (final round with 2 teams alive, tiny pools) — the "sensible
  handling". VOR = expected_points - replacement, computed per position pool then the
  skater+team rows are UNIONED and sorted by vor desc (tie: projection desc, name).

  "G", no quantiles). `build_cheatsheet` -> `CheatSheet` with `.summary()` (manifest)

- Multi-step recommendation (US-021, `optimize/recommend.py`): `recommend_pick(state,
  owner, model)` = argmax over legal candidates of expected FINAL owner-roster
  projection via MC rollout to draft end (opponents draft through all owner turns; owner

  NUMBERS: seed rollout j from j ALONE (not the candidate) so all candidates face the
  same opponent draws; without CRN the candidate value gaps (<0.5) drown in rollout

- Strategy comparison honesty (US-021): use SINGLE-DECISION same-slot framing ("from the
  same slot") — advance to a shared decision slot with a greedy tail, each strategy makes
  ONE pick, finish with an identical greedy-VOR tail; measure final owner value. Do NOT
  run each strategy at EVERY owner pick (recursive tail/policy mismatch: the rollout
  assumes a greedy tail but actual play uses lookahead -> biased, lookahead can lose).
  KEY FINDING: against BALANCED opponents greedy-VOR is already optimal (fitted opponents
  draft positions evenly because `rank_z` is standardized WITHIN a position), so
  multi-step correctly TIES it — a tie is the honest, expected result, not a bug. The
  multi-step advantage only appears against POSITIONAL-RUN opponents (a run pushes a
  position below its pool-wide replacement, where a static VOR board is blind) — the
  committed `artifacts/models/recommend/report.md` runs BOTH scenarios and reports both.
