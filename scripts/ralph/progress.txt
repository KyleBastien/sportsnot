## Codebase Patterns
- Package scaffolding: package.json with exports map, tsconfig.json extending root, tsconfig.lib.json with nodenext module resolution
- Path aliases go in root tsconfig.base.json paths
- Nx auto-infers typecheck target via @nx/js/typescript plugin — no need to add manually
- Lint is not per-project in Nx; use root `npx eslint <path>` directly
- Unit tests use rstest (yarn rstest <specific files>) — do NOT run bare `yarn rstest` as it picks up Playwright files
- E2e tests use Playwright against http://localhost:4200 (needs serve-static running)
- Nx sync prompt appears on first typecheck — answer "yes" to sync TS references
- tsconfig.json is auto-modified by Nx sync — commit changes after sync
- Scripts that import cross-package need separate tsconfig with `bundler` moduleResolution (not `nodenext`) — use tsconfig.scripts.json pattern
- Use `/* eslint-disable no-undef */` for Node.js scripts (process, setTimeout) since ESLint config doesn't set node env
- tsx is installed as devDependency for running TypeScript scripts
- nodenext moduleResolution requires `.js` extensions for relative imports — applies to barrel exports (index.ts) and any cross-file imports
- Types package (packages/types/src/index.ts) needs `.js` extensions in re-exports for nodenext compatibility
- Nx sync may revert manual tsconfig reference changes — let Nx manage project references
- Rspack DefinePlugin: add env vars to envVars object with process.env fallback, then JSON.stringify in DefinePlugin
- Nx typecheck for web fails (pre-existing) — use `tsc --noEmit -p packages/web/tsconfig.app.json` instead
- Mock mode code lives in packages/web/src/mock/
- Use React.lazy + dynamic import() inside build-time guard for mock-only components — enables Rspack dead-code elimination
- Playwright tests need `--config packages/e2e/playwright.config.ts` flag (bare `npx playwright test` picks up rstest files)
- MockWrapper pattern in app.tsx: conditionally wrap children with lazy-loaded provider using `if (!Comp) return <>{children}</>` guard
- Playwright full suite (86 tests) is slow; use smoke test (`packages/e2e/tests/smoke.spec.ts`) for quick validation
- AuthContext and AuthContextValue are exported from AuthContext.tsx — mock/test providers can reuse the same context
- Mock auth pattern: MockAuthProvider in main.tsx uses same AuthContext, lazy-loaded behind build-time guard
- Mock TanStack Query pattern: use makeMockQuery() helper that returns { data, isLoading: false, error: null, ... } matching UseQueryResult shape
- Mock TanStack Mutation pattern: use makeMockMutation() helper that returns { mutateAsync, mutate, isLoading: false, ... } matching UseMutationResult shape
- DraftPage inline useDraft returns Supabase snake_case: { draft_order, current_pick, draft_picks: [{ pick_number, player_id, league_members: { team_name, user_id } }] }
- Snake draft order is pre-expanded into flat array (members × rounds) — generateSnakeDraftOrder in useMockDraft.ts
- LeagueMember.user is typed as User (camelCase: displayName, avatarUrl), not snake_case — but Supabase responses use snake_case (display_name, avatar_url)
- Bot names pool: pull from fixture data players for realistic names
- Bot auto-pick: use BotAutoPickRunner (invisible component) inside MockDataProvider — triggers useBotAutoPick hook that monitors draft state
- Bot strategy: pick best available player by greatest positional need (5F/3D/2G targets), alphabetical tiebreaker
- Browser globals (setTimeout/clearTimeout) need `/* eslint-disable no-undef */` in web package files too
- Simulation state: accumulatePlayerStats and getRoundDateBounds are exported from MockDataProvider for reuse by standings/roster/scoring hooks
- Round game fixtures mapped in ROUND_GAMES: { 1: gamesR1, 2: gamesR2, 3: gamesCf, 4: gamesScf }
